# 《电商运营与智能问数中台系统》项目总结与答辩追问预演

## 1. 软件过程与项目总结

1. **过程复盘**：
   - 本项目严格遵循敏捷迭代开发模式（Agile/Scrum），通过 Sprint 1（脚手架与CRUD）至 Sprint 4（打包与交付物归档）的循序渐进，确保每个阶段均具备可运行的独立交付物，杜绝了一次性庞大堆砌代码导致的联调风险。
2. **质量与成果**：
   - 建立了全链路自动化测试体系，全工程共沉淀 **253 项单元与边界测试用例**，测试通过率 **100%**；
   - 顺利生成可独立运行的生产级 Jar 包（38.7 MB），内嵌 Web 容器与前端单页应用，支持跨平台一键部署。

## 2. 答辩高频追问预演与回答策略

### 追问 1：*“你的系统界面看起来既有商品管理表格，又有对话框，这两部分是如何协同工作的？”*
- **回答策略**：
  > “报告老师，这正是本系统‘AI 原生一体化中台’的设计核心。  
  > 传统的业务管理操作（如查看某个具体商品属性、修改价格）适合在**表格视图**中直观维护（CRUD）；而跨表、跨时间周期、复杂指标聚合（如‘查各省份客单价分布’）在传统界面中往往需要开发人员编写大量临时报表页面。  
  > 我们通过内嵌 **AI Copilot**，让运营人员在管理数据的同时，随时通过自然语言发起分析。AI 负责根据数仓拓扑生成标准 SQL 并由 ECharts 动态绘图，二者相辅相成，大幅降低了企业取数沟通成本。”

### 追问 2：*“大模型生成的 SQL 存在极高的高危风险（如删库），系统是如何做到绝对安全的？”*
- **回答策略**：
  > “系统设计了三层纵深安全防御机制：  
  > 1. **应用层 AST 语法树拦截**：使用 JSqlParser 对大模型生成的 SQL 进行语法树解析，白名单严格限制根节点只能是 `PlainSelect`，任何 `DELETE`、`DROP`、`UPDATE` 或恶意函数均在解析阶段被直接拒绝；  
  > 2. **数据库层物理只读账号**：AI 问数沙箱执行连接的是独立的 `text2sql_ro` 账号，数据库层面彻底剥夺了写权限，即使应用代码出现漏洞也绝不可能篡改数据；  
  > 3. **资源层超时熔断**：配置 10 秒超时与 200 行上限，防恶意慢查询拖垮数据库连接池。实测 44 项对抗性攻击拦截率达 100%。”
